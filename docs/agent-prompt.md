# 直接交给 Agent 的完整任务书

在项目目录中使用 Agent 时，可以把下面代码块整段发给它。没有参考图也可以先发送；Agent 应先引导你上传图片，再继续依赖图片的步骤。已有参考图时直接附在同一条消息中即可。

```text
请使用 Desktop Pet Template 为我制作并安装一个独立的 Windows 桌宠。
仓库：https://github.com/Howltan-Neo/desktop-pet-template

请执行任务并交付可运行成品。不要只给出计划、提示词、网页预览或素材目录。

【先准备项目，再引导我提供参考图】
1. 如果当前目录不是本项目，先在已授权的工作区内获取项目；不要覆盖已有文件。
2. 读取 README.md、AGENTS.md、docs/character-pack.md、docs/ai-workflow.md 和构建配置。
3. 如果我尚未提供参考图，先对我说：
   “请上传一张你希望做成桌宠的角色参考图，或告诉我本机图片路径。手绘、插画或清晰照片都可以；尽量让人物主体完整、五官和服装可辨认。你也可以只提供头像，我会先补全身体方案并给你看基准预览。角色名、主题色和性格可选，不填写时我会从图片提出默认方案。”
4. 等待参考图，期间只进行不依赖形象的环境和工具检查。不能把小安、小哞或其他样例当作我已经选定的角色。
5. 如果我已给图，直接使用。不要重复索要同一张图，也不要重复做完整需求问卷。

【默认方案】
- 目标平台为 Windows 10/11；保留项目现有的液态玻璃、角色主题色与附带字体风格。
- 从参考图提取配色与形象特征。没有指定名称、性格或细节时，采用简短、友好且符合图片的默认方案，写进任务书；不要逐项中断询问。
- 全新角色使用独立角色包与唯一 id。不要把人物姓名、具体肢体坐标、台词或帧数硬编码到 app/。
- 保留鼠标悬停、点击、长按、双击、拖动、键盘工作反馈、16 方向头脸跟随、主动陪伴、置顶、缩放、托盘和任务栏避让。
- 耳朵、发尾和尾巴等专属交互只在该形象确实具备对应部件时加入。
- 允许我提出自己的主题、字体、动作或台词偏好；普通实现细节由你判断。

【检查你的实际能力】
- 确认能读取本地文件、执行命令、使用图像生成或编辑工具、查看图像，并在 Windows 上构建与验证程序。
- 优先使用宿主已提供、当前任务允许使用的生图和视觉工具。
- 如需使用 API，先明确我已授权的服务、可用模型和调用数量或预算；密钥只在本地安全配置，不让我在公开聊天或仓库里粘贴。
- 如果缺少某项能力，说明具体缺项和最短的补齐方法，同时继续不受影响的工作。不能用模拟客户端、重复帧或占位图伪称生成完成。

【从一张图制作角色】
1. 保留参考原图并记录哈希。用 tools/ai_workflow.py plan 创建独立目录和 AI 制作任务书。
2. 识别并记录脸部、发型、五官、服装、配饰、身体比例和左右不对称等不可随意改变的特征。原图没画出的部分写为补充设计，不当成原图已有事实。
3. 先生成一张完整、透明背景的待机基准帧，给我查看；形象与补充设计确认后再批量制作。等待确认期间可以完善动作规划和环境。
4. 设计各动作的准备、发力、接触、回收及循环相位；独立绘制真实姿态变化和表情，不用整图缩放、平移、扭曲或复制凑帧。
5. 按角色包中的实际路径输出 RGBA PNG。一般动作按 6 帧、左右跑步按 8 帧、头脸方向按 16 帧作为起点；根据需要增加细节。每帧保持统一画布、比例、中心和基线。
6. 为各动作生成至少四条简短、自然、符合角色性格的中文台词，避免同轮重复。依据新角色真实位置设置 hotzones，并填写 theme、interactions 和必要的 aliases。
7. 使用已授权的 API 时，执行项目现有的 generate/review 命令，明确图片数量上限并利用断点续做；使用宿主生图工具时，也按同一角色包契约保存产物和记录。

【自检与修复】
1. 执行 validate_pack.py 与 qa_pack.py，导出全部动作的逐帧总览、GIF 和检查报告。
2. 对照原图、基准帧和全部动作循环，检查人物一致性、五官清理、眉眼、衣服、配饰、手脚数量、遮挡、重影、裁切、比例、落脚点及首尾衔接。
3. 跑步检查对侧摆臂和腿、重量转移与接地；摸头、拽发尾等动作检查接触和回弹；方向帧检查真实头脸朝向，不能只移动瞳孔。
4. 将问题写成“动作—帧号—问题—修复方式”。定点修复并保留旧稿，再生成预览和检查。修改图片后，旧的视觉评审结论不能继续当作新验收。
5. 区分结构检查、AI 视觉审查和人的验收。某项没有执行就写未执行；不能仅因文件存在或模型说通过就宣布自然真实、绘画完整。

【构建成我的桌宠】
1. 在不改动共享动作引擎的前提下，设置分发入口 run.py 的默认角色包或等效启动参数，让不带参数启动时显示我的角色。
2. 检查 DesktopPetTemplate.spec 的打包资源，分发时优先只包含我的角色包与必需的共享字体、光标、Tcl/Tk 等依赖；保留源码样例，无需删除它们。
3. 为独立发布同步程序文件名、图标、安装器 AppName、AppVersion、唯一 AppId、安装目录与快捷方式。不能让我的程序覆盖另一个独立角色的安装或仍默认启动样例。
4. 运行适当测试、资源检查和 Windows smoke 检查，然后用 PyInstaller 构建。需要安装版时，准备 Inno Setup 并构建安装器；编译器缺失要说明，不能把便携目录冒充安装器。
5. 便携交付必须包含完整目录及 _internal，不能只拿出 EXE。构建后若再修改源码或资源，重新构建并更新哈希。

【安装和最终验收】
1. 把生成来源、安装位置和将要安装的版本告诉我。若我尚未授权安装或系统要求交互确认，按宿主规则取得授权；已有授权不要重复索取。
2. 在目标 Windows 上验证打包后的程序，而不仅是 Python 源码。检查窗口显示、全部动作、对白、面板、缩放、置顶、托盘、退出及重启恢复。
3. 检查键盘输入与停止后的状态切换、鼠标方向、点击/悬停/长按/双击/拖动；在条件允许时验证跨屏、不同 DPI、自动隐藏任务栏和气泡避让。
4. 先在独立测试目录验证安装、启动、退出和卸载，再按我的授权安装正式副本；如只能进行部分验收，准确记录范围与剩余事项。
5. 最终交付：角色参考与约束、完整角色包、可编辑源码、动作预览与检查报告、完整便携目录、安装器（若已构建）、版本和 SHA-256、使用与卸载说明、真实完成和待验收项目。

请现在开始。如果还没有参考图，就先引导我提供一张图，然后按上述流程完成制作。
```

## 在已有角色基础上继续修改

在同一条任务中补充“沿用已经确认的基准帧，只修改指定动作或台词，并保留备份”即可。不要再次从原图重建所有素材，也不要覆盖已确认版本后才询问。
